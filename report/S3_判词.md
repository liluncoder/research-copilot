## 三、★脚本抓到的真 bug

标题树里 `6 Results` 这一节 **n_paragraphs = 0**（内容都在 6.1/6.2 子节里），
点它会**跳空**——判据 R5 第一次就是 FAIL。修法：给空父节补 `nav_para_id`，
指向后面第一个有内容的节的首页段落；前端把它显示成置灰的父节点，点击自动落到子节。
**这类问题肉眼很难发现，是判据脚本替我抓到的。**

## 四、已知限制（如实写）

1. **双栏是"文本双栏"（原文列 + 译文列），不是 PDF.js 像素级渲染**。
   理由：J5 的可演示点在"段落级联动 + 引用跳转"，而段落对齐必须建立在文本段落上；
   PDF.js 能渲染真实版式，但拿不到与译文一一对应的段落。后续若要"看起来像原版论文"，
   可加一个 PDF 预览抽屉（`GET /documents/{id}/pdf` 已就绪，浏览器内置查看器即可）。
2. **联动滚动是"段落顶部对齐"**，两侧行高不同时会有轻微跳动；
   已按 `路线/02` 的失败去向实现降级路径：**点段落/标题树可强制对齐**，关掉联动开关也能用。
3. 翻译按节懒加载：首屏翻前两节，其余滚动到才翻（每节一次 LLM 调用，约 2~4s）。
4. 划词未做（原文可自由选中复制，但没有"划词即翻译"浮层）——非 J5 判据要求。

## 五、人工验收清单（录 S3 素材时按这个走）

1. 打开 `/reader/{doc_id}`，确认左右栏同时出现同一段落的中英文
2. 拖动左栏 → 右栏同步跟随（关掉开关则不同步）
3. 点正文里的 `[11]` → 底部参考文献滚到第 11 条，正文里 3 个引用段落加左侧高亮条
4. 点参考文献某条 → 正文跳到第一个引用它的段落
5. 点标题树 `3.2.1` → 正文滚到该节首段，右栏同步

### 这一轮抓出的三个真问题（都已修）

1. **只认数字制引用 ⇒ Natural/NC 类论文的引用几乎为 0**
   01（Nature 系技术报告）原本只抽出 **3 处引用 / 2 条被引**，04（Neural Computation）是 **0 / 0**——
   因为它们写 `(Bellec et al., 2020)` 而不写 `[11]`。
   ⇒ 新增 `backend/app/services/citations.py`：数字制 + **作者-年份制**双支持（姓氏+年份建索引）。
   修后 01 → **86 处 / 39 条**，04 → **64 处 / 44 条**。判据新增 **R8** 守住这条。

2. **连字符分词把 `three-factor` 当整体** ⇒ 问 "three factor" 检索不到
   实测：问「e-prop 的三因子学习规则包含哪三个因子」时系统拒答，而原文里 `three-factor` 出现 3~5 次。
   ⇒ `bm25.tokenize` 对含连字符的词**同时产出整体与拆开两种形态**。修后用英文重问，
   能正确答出「eligibility trace / 全局奖励信号 / 调制因子」并挂 3 处出处。

3. **拒答判定与内容矛盾**：回答先写"库中未找到"、再解释原因并挂了出处，
   旧逻辑（有 key 且无出处才算拒答）把它判成"已作答" ⇒ 状态与内容打架。
   ⇒ 改为只看**开头 40 字**是否出现拒答语，不再要求无出处。J4 回归仍 10/10。

### 已知限制（这批论文暴露的）

1. **Nature 正文用上标数字引用**（`…dilemma^{1,2}`），既不是 `[12]` 也不是 `(Author, 2020)`
   ⇒ 02 这篇的引用标记仍只有 1 处。要彻底解决需在解析层识别**上标 span**（PyMuPDF 的 flag），
   属后续增强；当前策略是"宁可少认，不可错连"（S5 建图时不会因此连错边）。
2. **06 TESS 漏抽第 28 条参考文献**（编号 1..34 中缺 28）⇒ 正文引用 `[28]` 成为悬空引用。
   单篇单条，已在读者界面标注为悬空（点了不会跳空）。
3. **01 的"公式行"2073 条是误判**：该技术报告正文本身用数学字体排版，属已知的启发式边界
   （J2 判词已记录），不影响检索与阅读。
4. 表格：5/8 报"未识别到表格"——这批论文多为纯文本排版（Nature 系表格常以图形式出现），
   未逐一人工核对，暂按"可能确实无表"记。
