## 怎么做的（答辩要讲的）

**不用大模型、不用 Marker，靠排版启发式。** 理由：零边际成本、结果确定、可复跑、可解释。

先勘探出这篇论文的排版规律（脚本 `_explore.py` 已弃用，结论记录如下）：

- 正文 10.0pt 正体；**9.9 / 10.1pt 是同一字号的浮点噪声**，不能当成"不同级别"
- 一级标题 12.0pt 粗体；二三级标题 10.0pt 粗体
- ★编号与标题被 PDF 拆成两行（`3.1` 一行、`Encoder and Decoder Stacks` 一行）
- 公式用 Computer Modern 系列字体（CMR / CMMI / CMSY / MSBM…）渲染

于是三层规则：

1. 同块内 y 中心差 < 2.5pt 的片段合并回一个"视觉行"（修拆行）
2. 字号 ≥ 11.5pt 且粗体 ⇒ 一级标题
3. 粗体 + 以编号开头 ⇒ 层级 = 编号点号数 + 1（`3.2.1` ⇒ 三级）；无编号的 `Abstract` / `References` 靠字号判定

## 踩的三个坑（★都留了回归意识）

1. **页码被当成标题编号**：页眉的 `2` / `3` 也是纯数字，被"孤儿编号合并"逻辑抓到，跟下一行拼在一起 ⇒ **14 处误合并**，
   吃掉了附录标题 `Attention Visualizations`、污染了图注和参考文献条目。
   修：编号行与标题行**必须都是粗体**才允许合并（页码是正体，标题编号是粗体）。
2. **作者角标 ∗ 被当成公式**：∗ 用的是 CMSY 数学字体，导致"公式行 97"里混进了作者行 ——
   样例一打印就露馅（打出来是作者名单，不是公式）。这是**只报总数不给人看样例**的典型翻车。
   修：纯角标符号（`^[∗†‡]+$`）不算公式 ⇒ 92 行；并给每行记 `math_chars`，样例只取数学字符 ≥ 6 的行。
3. **页脚页码粘到最后一条文献尾巴上**：末条变成 `…ACL, August 2013. 12`。
   修：参考文献续行跳过纯数字行。

# 第二轮（10-17）：跨出版社泛化 —— 换一篇论文就崩

## 触发

李论自己找了两篇 e-prop 论文上传试解析（预印本 `01_Bellec2019`、Nature Communications
`02_Bellec2020`），报回四个问题：标题只识一行、作者完全没抽到、有标题识别成零字符、
第二篇连次标题都识别不出来。

**这不是"顺便修修"——第一版解析器把 arXiv 的字号规律写死在常量里，
换个出版社就废。写死阈值等于只支持一类排版。**

## 根因一：空格 span 被过滤掉（★最严重，是我的 bug）

`_page_lines` 里有一句 `spans = [s for s in line["spans"] if s["text"].strip()]`，
把**纯空格的 span 全丢了**，然后靠"间距 > 1.2pt 就补空格"的启发式。

而这类 PDF 把空格单独做成 span、相邻词首尾相接（gap = 0.00）⇒ 启发式完全失效：

```
实测：'Biologicallyinspiredalternativestobackpropagationthrough'
对照：PyMuPDF 原生 get_text('text') 是完好的
      'Biologically inspired alternatives to backpropagation through'
```

arXiv 那篇没暴露，是因为它的词是分开的 span、间距刚好够大 —— **纯属侥幸**。
这个 bug 会让整篇正文的单词粘成一坨，对 RAG 是毁灭性的。

修：保留空格 span，间距阈值改为随字号缩放（`max(1.0, 0.18 * size)`）。

## 根因二：标题判据写死了 arXiv 的字号

Nature 那篇的标题与正文**同字号**（9.5pt）、**没有粗体标记**、字体名还被混淆过
（`AdvOT1ef757c0` / `AdvOTcb88df00`）。任何写死的字号都失效。

改为**先统计这份文档自己的样式分布**，再判断哪些样式"用在短行上"：

| 约束 | 含义 |
|---|---|
| distinct | 与正文字体不同，或字号大 15% 以上 |
| rare | 该样式的行数 ≤ 正文行数的 20%（标题是稀疏的） |
| shortish | 平均行长在 6 ~ 60 字符之间 |
| light | 该样式占全文总字符 ≤ 15% |
| not_too_long | 该样式的**最长**行 ≤ 120 字符 |
| then_body ∨ has_known_name | 后面通常跟正文；**或**该样式里出现公认章节名（Results/Methods/References…） |

最后一条是这轮的关键补丁：Nature 的真标题 `Results` 后面紧跟的是**一个加粗的段首小标题**
而不是正文，只靠"后面跟正文"会把真标题否决掉。

## 过程中踩的坑（都留了回归意识）

1. **页码被当成标题编号**：合并后出现 `'4 Figure 1: Scheme and performance of e-prop 1 …'`。
   修：按页边距丢弃页眉页脚（`y/height < 0.08` 或 `> 0.94`，以及版面内孤零零的短数字）。
2. **字号浮点噪声被当成不同样式**：同一个 10pt 正文在 PDF 里报成 9.9 / 10.0 / 10.1，
   不归并会让"正文样式"只覆盖一部分，连带把"标题后面跟的是不是正文"判错
   （实测：`Abstract` 因此被漏掉）。修：样式键按 0.5pt 归并。
3. **"短行"这一个信号远远不够**：v1 第 15 页的图注里有
   `The / Law / will / never / be / perfect …` 一词一行，曾被判成标题样式
   ⇒ **标题数从 25 暴涨到 346**。修：加 rare / light / not_too_long / 平均行长 ≥ 6。
4. **段首小标题（run-in）切过头**：作者行 `Guillaume Bellec*, Franz Scherr*, …`
   里的角标 `*` 也是样式边界，于是作者名被切成了"标题"
   ⇒ 作者从 6 位掉成 2 位。修：行首片段必须首字母大写、≥2 个词、
   以句号/冒号收尾、不含公式符号。
5. **只有编号没有标题的行不判成标题**：否则 Nature 参考文献区的 `1.` 会把整个
   Reference 区一刀切断（实测 0 条）。编号行交给专门的合并逻辑。
6. **伪代码行号**：论文一的算法框里 `2 Simulate the network over the interval …`
   被判成标题。修：编号后必须跟首字母大写的词 + 样式最长行 ≤ 120。
7. **"CM 字体 = 公式"对 LaTeX 论文全线误判**：论文一的**正文就是** Computer Modern，
   结果报出 3023 行"公式"。修：按文档自己的字体占比排除文字字体（降到 2073，
   仍有残留，见下面的已知限制）。

| 输入 | `tests/fixtures/pdf/1706.03762v1.pdf`（15 页，含 4 张表） |

### 先证伪现成方案（★这一步不能省）

| 方案 | 实测结果 |
|---|---|
| PyMuPDF `strategy="lines"` | **0 张** —— 学术表是 booktabs 风格，没有竖线 |
| PyMuPDF `strategy="text"` | 把整页当一张表，产出 49~68 行垃圾 |
| PyMuPDF 混合 `text/lines` | 列被压扁：`Self-Atten Recurrent Convolutio Se` |
| 结论 | 都不可用 ⇒ 自研「rule 定边界 + 空白投影分列」 |

### 自研方案的四步（每步都是踩坑后定下的）

1. **用横线（rule）定表格边界**，不用 caption 所在栏位——
   Table 1 与 Table 3 都是**通栏表**（x 119~493 / 108~509），按栏位裁会直接截掉右半张表。
2. **表头/数据的分界 = 表头之后第一条"通栏" rule**——
   半宽 rule 是 `cmidrule`（BLEU / Training Cost 这种组头分隔），不能当界线。
3. **列边界用"跨行投票"**，不是把全表词一锅投影——
   表格里有**多行行**（`Transformer (base model)` 换行），它的数值位置与别行错开，
   一锅投影时离群词会把两列桥接（实测 Table 2 的 FLOPs 两列就是这么并住的）。
4. **表头按词切、数据按续行合并**——
   多行表头必须压成一行（否则前端/ RAG 看到两个残表头）；
   而续行合并只能作用于数据区，否则会把单格表头粘进上一行、再把第一行数据卷进表头
   （实测 Table 2 的 `ByteNet` 行被吞进表头）。

| Table 2 | p8 | **11×5** | 0.89 | 5 列（Model / 2×BLEU / 2×FLOPs）；8 个 EN-DE 数值全中 |
