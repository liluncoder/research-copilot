### 三个真问题与结论
1. **PaddlePaddle 3.3.1 oneDNN bug**：`ConvertPirAttribute2RuntimeAttribute not support`
   （`onednn_instruction.cc:118`）⇒ PaddleOCR 必须 `enable_mkldnn=False`。
2. **关 mkldnn 后 PaddleOCR 慢到不可用**（295 s/页）⇒ 换 RapidOCR 主力（39.8 s/页，快 7.4 倍，质量持平）。
   附带收益：依赖轻，Docker 镜像小一个量级（R4 风险减轻）⇒ `pyproject.toml` 里 Paddle 系降为 optional extras。
3. **判据里的"2 页 <120 s"取消**（自设阈值，官方无时限）。理由：同页 8 线程 48 s vs 16 线程 52 s
   无线程加速 ⇒ 沙箱限 CPU，时间阈值测环境不测代码。**降级为记录项**，写进 `路线/04` §三。

## 补记：修复"文档给的命令在 PowerShell 里跑不了"（14:10）

**症状**：李论照判词里的 `cd backend && PYTHONPATH=. python tools/run_j3.py` 在 PowerShell 5.1 报
`标记"&&"不是此版本中的有效语句分隔符` —— 两个错叠加：① PS 5.1 不支持 `&&`；② `PYTHONPATH=.` 是 bash 语法。

**根因在于我的交付形态，不是他操作错**：只要文档/脚本默认读者在 bash 里跑，Windows 用户必然卡住。

**修法（三件）**：
1. **脚本不再依赖 PYTHONPATH**：`run_j3.py` / `j3b_541pages.py` / `mem_stress.py` 全部加
   `sys.path.insert(0, str(Path(__file__).resolve().parents[1]))`，任意目录、任意 python 都能跑
2. **给 Windows 一个双击入口**：`backend/tools/run_j3.cmd`，自动挑解释器
   （项目 `.venv` → `~\.workbuddy\...\envs\default` → PATH python）+ 设 `PYTHONIOENCODING=utf-8`；
   ★必须 CRLF，且 `.gitattributes` 里加 `*.cmd text eol=crlf` 钉死（否则 checkout 变 LF 又坏）
3. **文档 6 处命令全换成 PowerShell 形式**，并在 `docs/本机启动手册.md` §4.1 加专节、
   `README.md` 加"判据复跑"表 + Windows 提醒

**顺带**：`run_j3.py` 加 `--pdf` 参数，UDL 到手后换源复跑也是一条命令。

**实测**：`.\tools\run_j3.cmd --j3b` 与 `--j3b --pdf <路径>` 均 exit 0、PASS。
→ 交付任何命令前，先想"他在哪个 shell 里敲"，并在该 shell 里真跑一遍。

## 补记 2：J2 后半（表格解析）过 —— 自研抽取器（15:00）

**判据**：`tests/verify_j2_tables.py` T1~T8，8/8 PASS。
- Table 1 = 5×4 conf 1.00（4 行层类型 + 复杂度/串行/路径长度）
- Table 2 = 11×5 conf 0.89（Model / 2×BLEU / 2×FLOPs，8 个 EN-DE 数值全中）
- Table 4 = 12×3 conf 1.00（11 行 parser 结果，含 93.3）
- Table 3 = 22×4 conf 0.90 —— **结构压扁**（原表 13 列稀疏超参表），已知限制

**先证伪现成方案（重要，别再重试）**：PyMuPDF 1.28 三种策略全废 ——
`lines` 找不到（booktabs 无竖线）、`text` 把整页当表（49~68 行垃圾）、混合策略把列压扁
（`Self-Atten Recurrent Convolutio Se`）。⇒ 自研「rule 定边界 + 空白投影分列」。

**四个必须记住的实现要点**（都是踩坑换来的）：
1. 用**横线（rule）**定表格边界，不能按 caption 所在栏位裁 —— Table 1/3 是通栏表（x 119~493 / 108~509）
2. 表头/数据分界 = 表头后第一条**通栏** rule；半宽 rule 是 cmidrule（组头分隔），不能当界线
3. 列边界用**跨行投票**（gap 中点按行投票，支持度过半才算边界）—— 一锅投影会被"多行行"的
   离群词桥接（Table 2 的 FLOPs 两列就是这么并住的）
4. **表头按词切、续行合并只作用于数据区** —— 否则单格表头行会被粘到上一行，再把首行数据卷进表头
   （实测 Table 2 的 ByteNet 行被吞）

**一个必须记下的核对结果**：Table 2 的 Transformer(big) EN-FR BLEU 抽出 **41.0**，
而大众记忆是 41.8。去原文文本层 `search_for("41.8")` → **空**，`search_for("41.0")` → p8 (336,230)。
⇒ arXiv **v1 原文就是 41.0**，抽取忠实，不是 bug。**判据必须锚定原文可核对的数值。**

**集成**：`ParsedDocument.tables` + `as_dict()` + `stats["tables"]`，API 自动带出；
`parse_pdf(..., with_tables=False)` 可跳过（纯文本用途省时间）。
