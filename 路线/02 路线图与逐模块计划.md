## 三·补、每个阶段做什么（发车前必读）

### S0 骨架（10-16~17）

- GitHub **Public** 仓库从第一天建（Git 历史要"养"，不能最后伪造）
- `frontend/`：Next.js 14 + TS + Tailwind + shadcn/ui 空壳；`backend/`：FastAPI + `/health`
- `docker-compose.yml` 一键起前后端；`README.md` 骨架；`.env.example`
- 判据：自判（非官方）——干净机器上 clone → `docker compose up` → 浏览器看到界面
- **失败去向**：Docker 起不来 ⇒ 先裸跑开发模式，S7 再补容器化（工程分只有 3%，别在这卡死）

### S1 解析（10-18~22）——对应 M1，判据 J1/J2/J3

- 上传（单篇/批量）+ 文献库 CRUD + 存储层
- 解析管线：**Marker**（PDF→Markdown，双栏/公式/表格一体）为主，PyMuPDF 兜底
- 扫描件分支：**PaddleOCR**（CPU 可跑，慢但用例只有 1 篇）
- **J1 语义去重**（★本阶段核心，**已于 10-16 完成**）：实际采用
  **正文 5-gram Jaccard（阈值 0.45，实测标定）** + 标题归一化匹配 + arXiv 版本号解析 ⇒ 弹预警；
  用户选覆盖/保留；高级行为：提示"库中已有较新版本" + 只喂统计量给 LLM 总结两版差异（结构性防幻觉）。
  ★原计划的"embedding 余弦 > 0.95"被实测推翻（无关中文论文余弦就有 0.948），详见 `report/J1_判词.md`。
- 541 页书籍：**流式解析 + 分批 embedding**，硬指标——容器内内存增量 < 2GB
- **失败去向**：Marker 公式烂 ⇒ 降级为"保留 LaTeX 原文 + KaTeX 渲染"，技术文档写已知限制

### S2 RAG（10-23~28）——对应 M2，判据 J4/J2，★全计划技术含量最高

- 切块：**基于标题树的结构化切块**（一级/二级/三级标题为边界，带元数据：论文 ID + 页码 + 章节路径）——这是区别于定长切块的创新点，技术文档重点写
- Embedding：**BGE-M3 本地 CPU**（零边际成本；多语言，中英翻译模块复用）
- 混合检索：Dense（Chroma）+ Sparse（BM25）双路召回，bge-reranker 重排（可选，CPU 跑得动就上）
- 回答契约（Guardrails）：**每个论断必须挂 `[来源: 文件名·页码·章节]`**；检索置信度不足 ⇒ 明确拒答"库中未找到"，不许硬答
- LangGraph 编排：`plan → retrieve → (multi_paper_compare) → answer` 多节点状态机，前端可视化 Agent 思考过程（对应评分"AI 思考与流式渲染"）
- 判据 J4：β1/β2 设置、GPU 型号与数量、BLEU 分数——三连问全中 + 出处锚点指向正确页段
- **失败去向**：句子级锚点不准 ⇒ 保段落级锚点（够打分），不追求句子级

### S3 阅读器（10-29~11-02）——对应 M3，判据 J5

- react-pdf（PDF.js）渲染单/双栏；文本层支持划词
- 标题树导航（S1 已抽好，直接复用）
- `[11]` ↔ References 双向无损跳转
- 中英对比 + **联动滚动**：按 PDF.js 文本块做**段落级对齐**，拖动一侧另一侧同步（★不做词级对齐，成本翻十倍且没必要）
- **失败去向**：联动滚动抖动 ⇒ 退化为"点击段落跳转对齐"，视频里照样能演示，文档写清楚

### S5 引用图谱（11-03~06）——对应 M5，判据 J6，创新性 10% 的主战场

- 参考文献解析（S1 已抽）→ 与本地库标题模糊匹配 → NetworkX 建图
- **基石论文挖掘**：PageRank + 度中心性双指标，前端可切换（对应评分细则原文 PageRank/Centrality）
- G6 前端渲染 20+ 节点，交互：点击节点高亮邻域、悬停显示摘要
- 附带产物：基于图谱的简短自动综述（LLM 只读图谱结构化数据，不读全文，控幻觉）
- **失败去向**：标题匹配率低 ⇒ LLM 辅助标准化参考文献格式，匹配率写进文档

### S6 写作 Copilot（11-07~10）——对应 M6，判据 J7/J8

- **J7 CSV→图表+caption**：pandas 算统计量 → ECharts 图；★★**caption 只喂统计量、不喂原始数据**（LLM 看到的只有 mean/std/趋势斜率等数字）⇒ 结构性防幻觉，技术文档里作为设计亮点写。★演示数据用神经系统2 `data/` 的真实仿真输出
- **J8 无幻觉 References**：论文框架（Abstract/Intro/Related Work）生成时，References **只能从本地库 + 真实 arXiv 检索结果里选**，编造一条都算失败
- 学术翻译：中文摘要 → 学术规范英文（BGE-M3 多语言 + LLM）
- **失败去向**：caption 泛泛 ⇒ 模板化"趋势 + 数值 + 结论"三段式，保底不难看

### S7 收尾（11-11~17）

见 `路线/07 提交与演示清单.md`。★铁律：每个阶段出口当天录 30s gip 存 `docs/demo/`，S7 只做拼接和补拍，不从零录。

## 五、逐层技术选型（★定稿，不许随手换）

| 层 | 选型 | 理由 | 备选 |
|---|---|---|---|
| 前端 | Next.js 14 + TS + Tailwind + shadcn/ui | 官方推荐首选；组件库把 UI 10% 的成本压到最低 | Vue3 + Nuxt3 |
| PDF 渲染 | react-pdf（PDF.js） | 官方点名；文本层支撑划词/跳转/联动 | 无 |
| 公式 | KaTeX | 快，够用 | MathJax |
| 图谱 | AntV G6 | 官方核心推荐；中文文档全 | Cytoscape.js |
| 图表 | ECharts | 折线/柱状/雷达现成 | Chart.js |
| 后端 | FastAPI + uv + Python 3.11 | 官方推荐；异步流式响应 | — |
| Agent 编排 | **LangGraph** | Task Planning + 多节点状态机，直接对应 9% 评分项 | LangChain |
| 向量库 | Chroma | 零运维、嵌入式、Docker 友好 | Qdrant |
| Embedding | **BGE-M3 本地 CPU** | ¥0 边际成本、多语言（翻译模块复用）、32GB 内存无压力 | API embedding |
| LLM | **DeepSeek-V4.1**（主，API 模型名 `deepseek-chat`）+ 通义千问/智谱（备） | 便宜、OpenAI 兼容、国内可达；双 provider 环境变量一键切换 | GPT-4o |
| OCR | **RapidOCR（onnxruntime）为主，PaddleOCR 兜底** | 2026-10-17 实测：RapidOCR 39.8 s/页（沙箱限 CPU），PaddleOCR 关 mkldnn 后 295 s/页；质量持平。且 RapidOCR 依赖轻，Docker 镜像小一个量级（R4 缓解） | GPT-4o vision（贵） |
| PDF→MD | Marker | 双栏/公式/表格一体，省事 | PyMuPDF 手搓 |
| 图计算 | NetworkX | PageRank/Centrality 现成 | igraph |
| 部署 | Docker Compose；演示放 HF Spaces Docker（免费 2C16G，不睡） | 规则要求 Docker 可复现；免费 tier 里唯一不睡的 | Render（会睡，✗） |

## 六、禁止清单（★禁止什么，比做什么更重要）

3. ❌ 不追句子级出处锚点（段落级够打分）
4. ❌ 不做多用户/登录体系（除非 S7 最后一天还有余量）
5. � 不引入第二套 UI 组件库（shadcn 默认皮肤改色即可）
