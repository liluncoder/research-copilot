## 零、方向（2026-10-16 新写）

### 0.1 目标的正确说法

- ❌ 不写"做个 AI 科研工具"。写：**「一个能过官方全部判据、评审期间在线可演示的全流程科研助手 Agent」**。
- 评委 3 人独立评分取平均分，35% 压在 Agent 技术深度上 ⇒ **技术深度 > 功能数量**。
  六个模块全做浅 = 每个都拿不到分；**四个模块做深（M1 解析 / M2 RAG / M3 阅读器 / M5 图谱）+ 两个做样子（M4 检索 / M6 写作）** 是更优解。

### 0.2 瓶颈排序（★写死，不许换序）

| 序 | 瓶颈 | 硬证据 / 理由 |
|---|---|---|
| 1 | **时间**（33 天 × 一个人） | 官方要代码仓库 + 视频 + 文档 + 在线演示四线齐交；任何"以后再说"都会变成 11-17 的灾难。⇒ 本计划一切设计以**每天有可演示增量**为准绳 |
| 2 | **抗幻觉 RAG 与源头溯源** | 单列 8%，且是 35% 权重里的核心；也是唯一"做不了假"的项——评分细则原文"精准的原文出处锚点"，评委一定现场点开验证 |
| 3 | **PDF 解析质量** | 7%；扫描件 OCR 与 541 页长文档是官方点名用例；本机无 NVIDIA、CPU-only，选型即风险（见 `05`） |
| 4 | **在线演示可用性** | 闭环 10% + UI/UX 10% 都要求"评审期间服务可用"；会睡的免费 tier ≠ 可用 |

### 0.3 三条不可越的边界

1. **判据未过 ≠ 功能不存在。** 演示时降级为"已知限制"，技术文档如实写。评分细则 d 项"测试用例通过率"只奖不罚，但违规条款（不实/抄袭）直接罚资格——**资格 > 面子**。
2. **API 密钥只进环境变量。** 仓库 Public 前跑一遍密钥扫描；这是规则原文，不是建议。
3. **AI 协同要留痕。** 规则明确鼓励 Vibe Coding，但技术文档必须写清"哪部分是 AI 写的、Prompt 怎么调的"——每天一条 commit message 就是现成证据链。

### 0.4 与神经系统2 的关系（边界）

神经系统2 提供三样东西，别的没有：

- **素材**：`data/`（2200+ json / 1200+ txt 仿真数据）→ 喂 M6 的 CSV 可视化判据 J7；`论文/`、`report/`、`docs/` → 喂 M1 的解析判据；
- **叙事**：演示视频开场的"我的真实科研痛点"——我在研究可持续学习的动力学系统，每天被文献淹没。这是创新性 25% 里别人抄不走的部分；
- **纪律**：计划表/路线图这套"判据先行 + 一次循环"工作法，本目录就是它的移植。

它**不**提供任何一行交付代码，也**不是**作品主题。

## 一、这套工作法本身（从神经系统2 移植的三条）

1. **判据先行**：先写死"怎么算过"，再写代码。判据迁就代码是本项目最典型的死法。
2. **一次循环**：任何功能都走 `路线/09` 的九步循环，不许"憋大招"。
3. **分篇按功能分，不按时间分**：`03 当前状态与瓶颈` 是唯一会经常变的那篇 ⇒ 它应该最短。
