# 05 工程算力与风险

---

## 一、这台机器能干什么（2026-10-16 确认，依据历史实测）

- Intel Core Ultra 7 255H（16C）/ 32GB DDR5 / Intel Arc 140T 集显 / **无 NVIDIA** / C 盘余 ~209GB
- ⇒ **不能把本地 LLM 推理当产品后端**。产品的 LLM 一律走 API；本地只跑 embedding / OCR / 图计算
- ⇒ BGE-M3 embedding 本地 CPU 可跑（32GB 宽裕；每篇论文 embedding 一次，批量 541 页也就几分钟级）
- ⇒ PaddleOCR CPU 可跑（慢，但扫描件用例只有 1 篇，可忍）
- ⇒ Next.js 构建 / Chroma / NetworkX / matplotlib 全部无压力

## 二、API 预算（★S2 发车前必须到位）

| 用途 | 选型 | 预估花费 |
|---|---|---|
| 对话 / 规划 / 对比 / 翻译 | DeepSeek-V3（OpenAI 兼容） | 开发+演示全程 ≤ ¥30（按量付费） |
| 备用 provider | 智谱 / 通义（免费额度） | ¥0 兜底 |
| Embedding | BGE-M3 本地 CPU | ¥0 |
| OCR | PaddleOCR 本地 CPU | ¥0 |

规则原文："使用商业大模型 API 须自行承担费用……鼓励结合开源大模型或本地部署轻量模型降低成本"——
本方案 ¥0 的部分（embedding/OCR 本地）就是为了这条，技术文档里要写进去。

## 三、在线演示（D4）方案

| 方案 | 费用 | 会不会睡 | 结论 |
|---|---|---|---|
| **HF Spaces Docker（2C16G）** | 免费 | 不睡 | **首选**；Docker 恰好是规则要求；16GB 装得下 Chroma + BGE-M3 |
| Render 免费 tier | 免费 | 15 分钟无请求就睡 | ✗ 评审期间不可接受 |
| Vercel（前端）+ HF Spaces（API） | 免费 | 前端不睡 | 备选：单容器跑不动前后端时拆分 |
| 自己 Windows 常开 + 内网穿透 | ¥0 | 看电网 | ✗ 不可靠，且违背"公网访问"精神 |

★待验证（11 月前必须实测）：① HF Spaces 国内评审专家可达性；② Docker 镜像构建时长（BGE-M3 权重 ~2GB，走构建期缓存或 persistent storage，R4）。
