## 二、纪律（★五条）

1. **判据先行**：发车前在本文登记 J 编号；没有 J 的功能砍掉或降级为"锦上添花"。
2. **未过 ≠ 不存在**：J 不过 ⇒ 演示视频明确说"已知限制"，技术文档如实写。
   评分只奖通过率，不罚未过；但违规条款罚资格——**资格 > 面子**。
3. **判据要能复跑**：每个 J 配固定输入（`tests/fixtures/`）+ 期望输出说明，
   评委 clone 后能自己复现。这是"输出成果可验证"规则原文的要求。
4. **不许改判据迁就代码。** 代码迁就判据。
5. 判词（怎么测的、结果、去向）落 `report/J<n>_判词.md`，然后回 `03` 更新状态、从 `06` 删掉完成行。

## 三、J3 判据展开（★2026-10-17 写死，不许改）

J3 实际是两条独立判据，必须分开测、分开记：

### J3-a 扫描件 OCR

| 项 | 值 |
|---|---|
| 输入 | `tests/fixtures/pdf/1706.03762v1_img.pdf`（无文本层，官方同构样本） |
| 判为扫描页的条件 | 单页去空白字符数 < **50**（`pipeline.TEXT_CHAR_THRESHOLD`） |
| 渲染 DPI | **150**（`OCR_RENDER_DPI`；150 与 200 的质量差异实测无差别，速度快 20%） |
| 通过条件（功能，四条缺一不可） | ① 每页判为 scanned；② 每页走 OCR；③ 每页字符数 > 500；④ 关键词命中 ≥ 2（`Attention`/`Transformer`/`BLEU`） |
| 反向条件（★防假通过） | 拿矢量 v1 跑同一管线，**必须 0 页被判 scanned** —— 否则说明检索把好页也送去 OCR 了 |
| **性能（★记录项，不作判据）** | 记录 s/页。**实测基线：本机 10.8 s/页（15 页扫描件 ≈ 2.7 min），沙箱 34.5 s/页（慢 3.2×，纯 CPU 限流）**。★2026-10-17 起取消"2 页 <120 s"这条自设阈值：官方赛题无时限要求，且沙箱限 CPU 已证（同页 8 线程 48 s vs 16 线程 52 s 无线程加速；两台机器差 3.2 倍），阈值只能测出环境快慢、测不出代码好坏。**改判据迁就代码是允许的，改判据迁就环境不行——所以这条直接降级为记录。** |
| 失败去向 | OCR 引擎全不可用 ⇒ 判不过，技术文档列已知限制；**绝不许静默返回空串** |

### J3-b 541 页内存硬指标

| 项 | 值 |
|---|---|
| 输入 | UDL 541 页（未到手时用 `_synthetic_541p.pdf` 或 `mem_stress.py --loop` 等价压力） |
| 测量口径 | `peak_rss - baseline_rss < 2048 MB`（`memory.MemoryProbe`） |
| 附加条件 | 内存曲线**不得线性增长**（采样点斜率 ≈ 0 才算过；线性上升即泄漏，判不过） |
| 通过条件 | ① RSS 增量 < 2048 MB；② 采样曲线呈平台化；③ 全程不崩 |
| 失败去向 | 超限 ⇒ 查是否整本进内存 / 页对象未释放；拆批重测并记录 |

**为什么压力模式合法**：J3 防的是"整本一次进内存"和"页对象累积"。
流式实现下二者均与总页数无关；`--loop` 把加载次数放大到 541 次，比真实场景更严格。
