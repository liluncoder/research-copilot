# 本机启动手册（Windows · 李论专用）

> ★这份手册是 S0 出口判据的执行稿，也是提交材料 D1 里"安装运行指南"的草稿。
> 目标：在你自己的电脑上，一条命令把前后端跑起来，浏览器里看到界面 + 后端显示"已连接"。
>
> 已完成的前置确认：本机 Docker 已装 —— `Docker version 29.4.1`、`Docker Compose version v5.1.3`。

---

## 第 0 步：启动 Docker Desktop

开始菜单搜 **Docker Desktop**，打开它，等左下角图标**从黄色变成绿色**（第一次可能要 1-2 分钟）。

判断方法：下面这条命令能打印出版本号就说明引擎活了。

```powershell
docker info --format '{{.ServerVersion}}'
```

报 `permission denied while trying to connect to the docker API` 或 `cannot connect to the Docker daemon`
⇒ Docker Desktop 还没起来，回去等图标变绿。

## 第 1 步：建 `.env` 文件（填你的密钥）

### 1.1 从模板复制一份

在 PowerShell 里执行（`cd` 先切到仓库根目录）：

```powershell
cd C:\Users\23810\Desktop\传智杯
Copy-Item .env.example .env
```

> ★`README.md` 里写的是 `cp .env.example .env`，那是 Linux/macOS 的写法；
> Windows PowerShell 用 `Copy-Item`（`cp` 在 PowerShell 里也能用，是别名，但记住这个区别）。

> ### ★★★ 铁律：`.env` 一旦建好，**永远不要**再跑这条 `Copy-Item .env.example .env`
>
> 它是**覆盖**，不是新建 —— 会把已经填好的密钥静默抹掉。
> 更坑的是 `Copy-Item` 会**继承源文件的修改时间**，所以覆盖之后文件看起来还是"几天前的老样子"，
> 完全看不出刚刚被改过（实测踩到：`.env` 与 `.env.example` 同为 1137 字节、同为 17:04:33）。
>
> 想确认密钥还在不在，跑这个（只打印变量名和长度，不打印密钥）：
>
> ```powershell
> python tools\check_env.py
> ```
>
> 填好密钥之后，养成备份习惯：`Copy-Item .env .env.bak`
> （`.env.*` 已在 `.gitignore` 里屏蔽，备份文件不会进仓库）。

### 1.2 用记事本打开，只填这三行

```powershell
notepad .env
```

`docker-compose.yml` 里写的是 `env_file: .env`，意思是：**整个 `.env` 会被注入到后端容器里**。
所以你只要保证这两行的等号后面有内容：

| 行 | 填什么 |
|---|---|
| `LLM_PROVIDER=deepseek` | **保持不动**，除非 DeepSeek 欠费了，才改成 `dashscope` |
| `DEEPSEEK_API_KEY=` | 你从 platform.deepseek.com 拿的 key，形如 `sk-...` |
| `DASHSCOPE_API_KEY=` | 你从 dashscope.aliyun.com 拿的通义 key，形如 `sk-...` |

其余的行（`ZHIPU_API_KEY`、模型名、路径、端口）**现在都不用动**。

### 1.3 三条铁律（写错了会 401 或读不到）

1. **不要加引号**。写 `DEEPSEEK_API_KEY=sk-abc123`，不要写 `DEEPSEEK_API_KEY="sk-abc123"`。
2. **等号两边不要有空格**。`DEEPSEEK_API_KEY=sk-abc123`，不是 `DEEPSEEK_API_KEY = sk-abc123`。
3. **key 里不要换行**。整串必须在一行里，别被记事本自动折行骗了 —— 保存前拉宽窗口看一眼。

保存时编码选 **ANSI 或 UTF-8**（不要选 UTF-8 with BOM）。最简单：这个文件里全是 ASCII 字符，随便存都行。

### 1.4 自检 + 确认它不会被提交进仓库

```powershell
python tools\check_env.py
```

输出里两个 `✓` 就说明 key 到位了；如果看到"内容与 .env.example 完全相同"的警告，
说明你刚被 `Copy-Item` 覆盖过，回 1.1 重填。

```powershell
git status --short
```

输出里**不应该出现 `.env`**（只可能出现 `frontend/Dockerfile` 之类的代码改动）。
如果 `.env` 出现在列表里 ⇒ 立刻停下告诉我，这是密钥泄露事故。

> 这个防护是 `.gitignore` 第 8-10 行做的（`.env` / `.env.local` / `.env.*.local`），已经配好了。

## 第 2 步：一条命令跑起来

确认当前目录是仓库根（`C:\Users\23810\Desktop\传智杯`，能看到 `docker-compose.yml`），然后：

```powershell
docker compose up --build
```

会发生什么：

1. 下载 `python:3.11-slim` 和 `node:20-alpine` 两个基础镜像（首次约 300-500MB，看网速）
2. 后端：装 FastAPI 那几个包（很快）
3. 前端：`npm install` + `next build`（★最慢的一步，首次 5-20 分钟，画面会停住不动，**不是卡死**）
4. 两条 `Started` 日志后，两个容器跑起来

**看到类似下面这样就算成功：**

```
research-agent-backend  | INFO:     Application startup complete.
research-agent-frontend | ▲ Next.js 14.2.15
research-agent-frontend | - Local:        http://localhost:3000
```

> 想让它跑在后台、把终端还给你：加 `-d`，即 `docker compose up -d --build`。
> 想停：`Ctrl + C`；后台模式则用 `docker compose down`。

## 第 3 步：验收（★这一步才是判据，别跳）

打开浏览器，看两个地址：

| 地址 | 应该看到 |
|---|---|
| http://localhost:3000 | 标题「科研助手 Agent」，右上角徽章是绿色 **已连接**，下面有六大模块卡片 |
| http://localhost:3000/library | **文献库**：上传 PDF ⇒ 看到解析出来的标题树（S1 的功能页） |
| http://localhost:8000/docs | FastAPI 自动生成的接口文档页（Swagger UI） |

然后在 3000 页面的「后端连接状态」卡片里，找这一行：

```json
"llm_configured": true
```

- `true` ⇒ **密钥读到了，第 1 步写对了**。
- `false` ⇒ 密钥没读到，八成是变量名拼错或等号旁有空格，回 1.3 检查。

**验收动作**：截一张 3000 页面的图（带绿色"已连接"和 `llm_configured: true`），存到 `docs/demo/`。
这张图就是 G3 判词缺失的那块证据，也是以后录视频的素材。

单看后端接口也可以：

```powershell
curl.exe http://localhost:8000/health
```

### 4.1 跑 J3（OCR + 内存）——★这一步和别人不一样，要进 backend

J3 依赖 `pymupdf` / `rapidocr` 这些后端库，所以它跑在 `backend\` 里，
而且**不要用 `&&` 连接命令**（PowerShell 5.1 不支持），一行一行来：

```powershell
cd C:\Users\23810\Desktop\传智杯\backend
.\tools\run_j3.cmd
```

`run_j3.cmd` 会自动挑解释器（项目 `.venv` → `~\.workbuddy\...\envs\default` → `PATH` 里的 python），
你不需要自己设 `PYTHONPATH`，也不用管 `python` 指向哪一个。

只想跑其中一条：

```powershell
.\tools\run_j3.cmd --j3a     # 只跑扫描件 OCR（约 1-2 分钟）
.\tools\run_j3.cmd --j3b     # 只跑 541 页内存（约 10 秒）
```

## 常见报错对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `env file .../.env not found` | 第 1 步没做 | 回第 1 步 `Copy-Item` |
| `project name must not be empty` | 仓库目录名是中文「传智杯」，被 Compose 剥成空串 | **已修**（`docker-compose.yml` 顶部写死 `name: research-copilot`）；临时可用 `docker compose -p research-copilot up --build` 顶一下 |
| `failed to compute cache key: "/app/public" not found` | 缺 `frontend/public/` 目录 | **本次已修**（补了 `frontend/public/.gitkeep`），重新 build 即可 |
| `cannot connect to the Docker daemon` | Docker Desktop 没启动 | 回第 0 步 |
| `Bind for 0.0.0.0:3000 failed: port is already allocated` | 3000 或 8000 被别的程序占了 | `netstat -ano \| findstr :3000` 查到 PID，`Stop-Process -Id <PID>`；或改 `docker-compose.yml` 的端口映射 |
| `npm ERR! network` / `ETIMEDOUT` 卡在 npm install | 网络挡了 npm registry，或校园网不稳 | 换网络重试；或在 `frontend/Dockerfile` 的 `npm install` 前加一行 `RUN npm config set registry https://registry.npmmirror.com` |
| 页面显示"未连接"但容器在跑 | 后端启动慢/崩了 | `docker compose logs backend` 看报错 |
| 改了 `.env` 但没生效 | `env_file` 只在**容器创建时**读一次 | `docker compose up -d --force-recreate backend` |

## 两个现在不用管、以后要记住的坑

### ★构建慢：默认已改用国内镜像源

直连 PyPI / npmjs 在国内会慢到不可用（实测：`uv pip install` 里 **pydantic-core 一个包下了 18 分钟**）。
所以 `backend/Dockerfile` 与 `frontend/Dockerfile` 的默认源分别改成了阿里云 PyPI 与 npmmirror，
并且可以在不改代码的情况下切回来：

```powershell
# 海外构建 / 镜像不可用时
docker compose build --build-arg PIP_INDEX_URL=https://pypi.org/simple --build-arg NPM_REGISTRY=https://registry.npmjs.org

# 或者写进 .env（compose 会读）
# PIP_INDEX_URL=https://pypi.org/simple
# NPM_REGISTRY=https://registry.npmjs.org
```

★**这条对评审同样成立**：评委在国内 clone 后构建，如果卡 40 分钟，工程分（架构可复现性与部署 3%）就没了。
所以镜像源不是"图自己方便"，是交付质量的一部分。

> npm 那边还有个细节：只设 `registry` 不够 —— `package-lock.json` 里记着 `registry.npmjs.org`
> 的绝对地址，npm 会照着 lock 里的 `resolved` 去下。所以 Dockerfile 里同时把 host 替换掉
> （只在镜像内改，不动仓库源文件）。

1. **`NEXT_PUBLIC_API_URL` 是"构建时"烧进前端代码的**，不是运行时读的。
   本地 Docker 构建没传这个变量，所以前端用了代码里的兜底值 `http://localhost:8000` —— 本地正好对。
   **HF Spaces 改成同源方案**：构建期传空串，前端发相对路径，由 `next.config.mjs` 的 rewrite
   转发到容器内的 uvicorn（7860 → 127.0.0.1:8000）。这样公网只暴露一个端口，也不再需要
   把公网地址烧进构建产物。
2. **`chroma_data` 是 Docker 命名卷，`data/uploads` 是本地目录。**
   删容器不会丢数据；但 `docker compose down -v` 会连卷一起删 —— **别随手加 `-v`**。

## 在线演示（G20）

### ModelScope 创空间（主路线，国内直连）

1. 登录 <https://modelscope.cn/>（手机号 / 阿里账号）。
2. 新建创空间：名称 `research-copilot`，SDK 选 **Docker**，可见性公开。
3. 头像 → 账号设置 → 访问令牌，新建并复制 `ms-...`（不要写进仓库）。
4. 生成 staging 并推送（`docker.yaml` 会被一起带上，平台据此走 Docker 构建）：

```powershell
python tools\deploy_hf.py
$env:MODELSCOPE_TOKEN='ms-...'
python tools\deploy_modelscope.py --repo <你的用户名>/research-copilot
```

5. 到创空间页面点「上线 / 重启」触发构建；在设置里加环境变量 `DEEPSEEK_API_KEY`。
6. 构建完成后验：

```powershell
python tools\verify_deploy.py https://modelscope.cn/studios/<你的用户名>/research-copilot
```

创空间对外端口固定 **7860**，正好是镜像里 Next 的端口；后端 uvicorn 仍在容器内 127.0.0.1:8000。

### HF Spaces（备选，需要 PRO）

> 2026 年起 Docker / Gradio Space 在免费 cpu-basic 上要 PRO；Static Space 才免费。
> 当前账号 `isPro=false`，所以 HF 只作为备选。

```powershell
hf auth login
python tools\deploy_hf.py --upload --set-secret --wait
```

`--set-secret` 会把 `.env` 里的 `DEEPSEEK_API_KEY` 写成 Space Secret（不打印值）；
`--wait` 轮询构建状态，直到 RUNNING 或报错。

如果不想让脚本上传，`build/hf-space` 本身就是 Space 仓库根，可以手动推：

```powershell
cd build\hf-space
git init
git add .
git commit -m "deploy: research copilot demo"
git remote add origin https://huggingface.co/spaces/<你的用户名>/research-copilot
git push -u origin main
```

（先在网页新建一个 **Docker** SDK 的 Space，名字 `research-copilot`。）

构建期会：装 CPU 版 torch → 装后端依赖 → 下载 BGE-M3（优先魔搭，失败再走 HF）
→ **用 BGE 重建 9 篇 / 845 块索引** → 构建 Next standalone。
运行时 uvicorn 只监听 127.0.0.1:8000，Next 监听 7860。

两个必须知道的点：

- **`STORE_BACKEND=numpy`**：镜像里装了 chromadb，若走 `auto` 会切到空的 Chroma collection，
  预置的 numpy 索引就白建了。Dockerfile 里 reindex 与运行时都固定 numpy。
- **只配 `DEEPSEEK_API_KEY`**（ModelScope 创空间设置 / HF Space Secret）。
  没配也能跑解析/检索/阅读/图谱，问答与图注会明确提示"未配置 LLM"。

## 密钥安全三条（规则原文要求："API 密钥不得出现在公开仓库中"）

1. `.env` 永远不进 Git（已由 `.gitignore` 兜住）；提交前我会再做一次全仓库密钥扫描。
2. **不要**把 key 贴进聊天、微信群、截图里。上面那张验收截图，保证截的是浏览器页面，不是记事本。
3. 万一怀疑泄露：去对应平台后台**直接吊销重发**，比任何补救都快。

★★**不要运行 `docker compose config` 并截图/录屏** —— 它会把 `.env` 里的所有变量
（包括 `DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`）**原样打印到终端**。
用它排查语法问题没问题，但别让它的输出进任何会外传的东西（截图、视频、群里）。
录演示视频时尤其注意：终端窗口要么关掉，要么切到别的目录。
